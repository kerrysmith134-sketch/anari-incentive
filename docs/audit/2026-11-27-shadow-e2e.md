## 2. 为什么是“真实执行 API”，不是 mock

`scripts/shadow-e2e.ts` 使用与生产相同的组装方式：

```ts
const platformStore = new MemoryPlatformStore({ demoTenant: {...} });
const store = new Store();
const app = buildApp(store, undefined, undefined, platformStore);
await app.inject({ method, url, headers, payload });
```

因此每个步骤都真实经过：

- Fastify 路由、请求 schema（Zod）、鉴权/角色、租户隔离、`onRequest` 钩子；
- `IncentiveStore` 的状态机（工作包、申报、归属、计算、台账）；
- `policy-dsl` 的 `calculateByPolicy` / `scorePerformance` / 定点金额；
- `MemoryPlatformStore` 的导入幂等、目标卡/快照、JEV checker、奖励批次命令、支付回执、GL 凭证、ACK 对账。

没有 stub controller、没有 mock 金额、没有直接改 store 状态来跳过业务规则。唯一“非网络”的边界是银行/ERP 外部系统：支付回执通过真实 `POST /incentive-award-batches/:id/payments` 接口写入，和集成回调走同一套校验与记账逻辑。

## 9. 缺口与不覆盖范围（必须知道）

1. **内存 store 不是 PostgreSQL**：本链路验证的是端口、路由、状态机、policy-DSL、定点金额与对账不变量；没有验证 PG 事务、行锁、唯一索引、迁移。`npm run test:pg` 仍是发布前必需。
2. **没有走真实连接器 HTTP 拉取**：fixtures 以真实 API 请求体导入，覆盖导入/幂等/映射契约，但不覆盖 OAuth、分页、重试、限流。
3. **Commercial 订单有前置链**：`importCommercialOrder` 要求已存在 ACCEPTED quote + SIGNED contract，因此同一 fixture 也导入 Account/Opportunity/Quote/Contract；不是额外业务场景。
4. **计算→批次没有自动写入端点**：脚本显式把锁定计算行映射为批次行，`sourceRecordId=<runId>:<lineKey>` 保证可回查。生产若需要自动批处理，需要新增业务端点（本任务禁止）。
5. **FX 是静态 fixture 7.10**：逐行 HALF_UP 2 位；没有接入实时汇率提供方或汇率治理流程。多币种折算的会计政策需财务确认。
6. **法人主体是维度字符串**：来自劳动合同、支付与 GL 的 `legalEntityId`；本任务未新增法人主数据 API。
7. **绩效只覆盖 E001/E003**：代表 CNY/USD 两个法人；E002 只参与奖金支付，不重复走目标卡（避免把 USD/CNY 覆盖写成 3 套评分）。
8. **JEV 未走 AI 建议**：本场景只要求人工判断 + 服务端 verify + 授权决定；AI_MODEL 的 403/建议不落决策已由 `jev-decision.test.ts` 覆盖。
9. **ACK 是 API 回执，不是银行网络 ACK**：外部银行文件/回执传输不在仓库内。
10. **审批是奖励批次命令 APPROVE**：没有走独立 approval-request 流程；该流程由其他测试覆盖。
11. **测试与脚本共享同一执行函数**：保证命令与测试跑的是同一条链；独立 oracle 由 `expected.json` + 测试中的显式断言提供，但不是第二套独立实现。

## 10. 失败时怎么定位

- 先看 `RESULT: FAIL` 后的 `FAILED CHECK <id>`：expected/actual/source 已打印；
- 用 `npx tsx scripts/shadow-e2e.ts --json` 获取完整 `steps[].checks[]` 与 `steps[].evidence`；
- `result.evidence.failedStepIds` / `failedCheckIds` 给出失败阶段与断言；
- 若第一个失败阶段是 `02.setup`，通常是端口/路由组装问题；若是 `08.performance`，先看目标卡锁定与快照 contentHash；若是 `12.payments-gl`，先看支付金额/币种/法人维度与 GL 科目。
