# 首个 wedge：充电桩 / 光储充项目

**日期**：2026-10-27  
**适用对象**：Anari Energy 及同类充电桩/光储充企业  
**状态**：P0 试点设计，待用 5–10 个真实项目验证

> 一句话：充电桩/光储充项目是 N-Perform 的天然 wedge——项目金额高、参与方多、交付链长、回款周期长、证据分散在 CRM/ERP/项目/施工/并网/财务系统，最容易出现“订单是谁的、交付是谁的、回款算谁的”争议。

---

## 1. 为什么充电桩行业适合做首个 wedge

| 特征 | 对贡献/激励系统的含义 |
|---|---|
| 项目制、金额高 | 单个项目贡献差异大，不能用固定岗位系数平均分 |
| 多参与方 | 销售、方案、采购、交付、施工、并网调试、运维、财务共同影响结果 |
| 长周期、分期回款 | 签约不等于回款；质保金/尾款可能跨年；激励必须与现金/验收挂钩 |
| 证据分散 | CRM 商机、ERP 成本/发货、项目任务、施工验收、并网报告、财务回款 |
| 外部依赖强 | 电网接入、客户现场、土建、设备交期会影响结果，不能全归个人 |
| 安全/质量风险高 | 充电站涉及电气安全、施工安全、并网合规；不能只看销售额 |
| 渠道/EPC/分包 | 伙伴、分包商、内部团队的贡献边界容易争议 |
| 强合规/审计 | 央企/国企/政府客户、补贴、招投标、质保、发票、关联交易 |

这些特征让“订单收入直接分给销售”明显不够，也让“通用绩效表单”无法解释项目贡献。N-Perform 的工作包+证据+贡献认定+确定性结算，正好对应这个行业的真实问题。

---

## 2. 买家与 champion

- **经济买家**：CFO/COO（关心项目毛利、回款、错付/漏付、审计）。
- **champion**：销售运营/项目管理办公室（PMO）/财务 BP（关心对账、周期、争议）。
- **gatekeeper**：HR/法务/内控（关心程序、合规、员工关系）。
- **不是 CHRO 单人采购**：充电桩企业的绩效痛点往往在“项目奖金怎么分”，而不是“绩效表单好不好填”。

---

## 3. 订单类型（首期只选一种）

| 类型 | 说明 | 首期建议 |
|---|---|---|
| **DC 快充站 EPC** | 设备+施工+并网+调试，金额大、参与方多 | **推荐作为首个 wedge** |
| AC 目的地充电 | 商场/园区/社区，金额较小、标准化程度高 | 第二期 |
| 光储充一体化 | PV+BESS+充电，技术复杂、成本结构复杂 | 第二期/第三期 |
| 充电站改造/扩容 | 存量站增加桩、升级功率 | 可作为轻量场景 |
| 充电桩设备销售 | 纯设备交付，链路短 | 可复用标准订单政策 |
| 充电站 O&M | 运维 SLA、可用率、工单 | 单独政策，不要和 EPC 混算 |

首期建议：**一个法人、一个区域、DC 快充站 EPC、5–10 个项目、20–50 人、一个季度**。

## 4. 工作包模板（DC 快充站 EPC）

| 工作包 | 主责角色 | 关键交付 | 验收/证据 |
|---|---|---|---|
| 商机与客户关系 | 销售负责人 | 商机、客户决策链、合同/框架协议 | CRM 商机阶段、合同、客户确认 |
| 选址/现场勘察/电网接入可行性 | 方案/开发 | 选址报告、电网接入方案、现场条件 | 勘察报告、电网答复、客户确认 |
| 方案设计/电气设计/设备选型 | 方案工程师 | 一次/二次图、设备清单、技术协议 | 设计评审、客户/电网确认、BOM |
| 采购/供应链/成本 | 采购 | 供应商定点、成本目标、交期 | 采购订单、比价、成本台账 |
| 生产/发货/物流 | 供应链/制造 | 设备生产、发运、到货 | 生产记录、发货单、签收 |
| 土建/安装/施工 | 交付经理/施工 | 基础、布线、设备安装 | 施工日志、隐蔽工程验收、照片 |
| 并网/调试/联调 | 调试工程师 | 并网、功率测试、平台接入 | 并网验收、调试报告、客户签收 |
| 项目验收/移交 | 交付经理 | 竣工验收、资料移交 | 验收单、客户签章 |
| 回款/质保金 | 财务/销售 | 进度款、尾款、质保金 | 银行回款、发票、合同条款 |
| 运维交接/O&M | 运维 | 交接、SLA、备件 | 交接单、工单、可用率 |

**原则**：工作包不是越细越好；首期每个项目 8–12 个工作包即可。C 级/胶水工作（协调、文档、客户关系维护）不要逐项定价，但要进入团队/岗位记分卡。

## 5. 证据地图

| 证据 | 来源系统 | 用途 | 风险 |
|---|---|---|---|
| 商机阶段/客户决策链 | CRM | 商机贡献 | CRM 阶段可被人为推进 |
| 合同/技术协议 | CRM/合同系统 | 范围、金额、付款条款 | 合同版本多，需版本化 |
| 项目成本/BOM/采购价 | ERP | 毛利、成本节约 | 成本分摊/关联交易 |
| 发货/到货/签收 | ERP/物流 | 交付贡献 | 到货≠安装完成 |
| 施工日志/隐蔽验收 | 项目/飞书/施工 App | 施工贡献 | 分包商代填、照片造假 |
| 并网/调试报告 | 并网/调试系统 | 调试贡献 | 外部电网延迟 |
| 客户验收/签章 | 客户/项目 | 验收、回款前提 | 验收标准模糊 |
| 回款/发票/质保金 | 财务 | 现金贡献 | 回款归属、坏账 |
| 工单/可用率/SLA | O&M 系统 | 运维贡献 | 工单数量≠质量 |
| 安全事件/整改 | EHS/项目 | 质量/安全门禁 | 瞒报 |

**证据覆盖率**：销售/交付/财务通常覆盖较好；方案、采购、调试、运维的“胶水工作”容易缺失。首期必须按角色测覆盖率，不要只看总体。

## 6. 贡献维度（建议）

| 维度 | 评估问题 | 证据 |
|---|---|---|
| 商机与客户关系 | 是否推动客户决策、拿到合同/框架？ | CRM 阶段、客户会议、合同 |
| 方案与技术 | 方案是否被客户/电网接受、是否减少变更？ | 设计评审、技术协议、变更记录 |
| 成本与采购 | 是否守住目标成本、交期、质量？ | BOM、采购价、成本台账 |
| 交付与施工 | 是否按期、按质、安全完成？ | 施工日志、验收、整改 |
| 并网与调试 | 是否一次并网成功、功率达标？ | 并网报告、调试记录 |
| 质量与安全 | 是否有事故、返工、客户投诉？ | EHS、验收、工单 |
| 回款与现金 | 是否推动进度款/尾款/质保金？ | 银行回款、发票 |
| 客户成功/运维 | 是否顺利交接、SLA 达标？ | 交接单、可用率、工单 |
| 协作与风险 | 是否解除阻塞、跨团队协调、提前暴露风险？ | 依赖记录、会议结论、受益方确认 |

**不要**把“参与过”自动等于“贡献”；也不要把“项目金额高”自动等于“每个人都贡献高”。

## 7. 参考政策：CHARGING_PROJECT_CONTRIBUTION_V1

这是首个租户的可执行参考政策，不是 Anari 的最终制度；数值需财务回测、法务审查、员工程序后生效。

```
basePool = min(项目毛利 × 4%, 150,000)
cashFactor = min(1, 已回款 / 合同额)
cashAdjustedPool = basePool × (60% + 40% × cashFactor)
retention = cashAdjustedPool × 5%        # 质保金，暂不分配
payablePool = cashAdjustedPool − retention
个人金额 = payablePool × 经确认的贡献权重
```

**质量门禁**：

- 客户验收未完成 → 阻断；
- 存在未关闭的安全事故 → 阻断；
- 回款为 0 → 仍可算，但池按 60% 计；建议试点期先不发放，只做影子；
- 退款/坏账/质保扣款 → 通过 adjustment/reversal 处理，不覆盖历史。

**为什么这样设计**：

- 把“签约”与“回款”分开，避免销售签单拿钱、公司垫资；
- 把“质保金”显式化，避免当期发完、后期无钱可扣；
- 把安全/验收作为硬门禁，避免“带病并网”；
- 贡献权重来自工作包+证据+人工认定，不按岗位平均分。

**参考 fixture**：`fixtures/orders/charging-001..005.json`，覆盖正常、全额回款、低回款、封顶、四人协作。

## 8. 行业特有的风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 项目成本超支 | 采购涨价、返工、窝工 | 成本台账、变更单、成本节约/超支进入贡献维度 |
| 电网接入延迟 | 外部因素导致并网延期 | 区分可控/不可控；不把外部延迟算个人失败 |
| 安全事故 | 施工/电气事故 | 安全门禁；事故未关闭不发/缓发 |
| 质保金/尾款 | 跨年回款、扣款 | 显式 retention；clawback/调整；不覆盖历史 |
| 进度款/现金流 | 垫资、回款慢 | 现金因子；财务 BP 确认回款 |
| 分包/EPC 伙伴 | 贡献边界争议 | 伙伴贡献单独记录；不自动并入内部员工 |
| 渠道/居间 | 佣金/返点 | 单独政策；与内部贡献互斥/叠加规则 |
| 政府补贴 | 补贴到账不确定 | 不计入个人池，或单独延迟发放 |
| 关联交易 | 利润/成本可操纵 | 财务审计、转移定价、独立复核 |
| 收入确认 | 完工百分比/验收节点 | 以财务确认的口径为准；不按合同额直接发 |
| 设计变更/范围蔓延 | 变更未留痕 | 变更单、验收标准版本化 |
| 设备序列号/站点资产 | 设备与项目对不上 | 稳定 site_id/设备序列号；证据关联 |
| O&M SLA | 可用率/工单质量 | 单独 O&M 政策；不与 EPC 混算 |

## 9. 试点范围与验收

**范围**：1 个法人、1 个区域、DC 快充站 EPC、5–10 个项目、20–50 人、1 个季度；手工证据 + 1 个真实连接器（CRM 或 ERP）；影子结算，不产生付款效力。

**验收指标**：

- 证据覆盖率 ≥70%（按角色分层；销售/交付/财务/方案/采购分别看）；
- 员工补充证据 ≤30 分钟/周期；项目经理复核 ≤2 小时/周期；
- 贡献争议率 <10%；申诉处理时限可满足；
- 财务对账差异 0；独立 CSV/表格复算差异 0；
- 安全/验收门禁 100% 生效；
- 员工信任/程序公平不低于基线；
- 法律门禁（民主程序、告知/签收、最低工资/扣款、DPIA）完成。

**Kill criteria**：证据覆盖率 <50%；员工 >30 分钟；争议率 >10%；财务无法对账；安全/验收门禁被绕过；法律审查不通过；员工普遍认为这是监控系统。

## 10. 首期明确不做

- 不做完整项目管理/甘特图/资源排程；
- 不做充电站运营收益分成（先做 EPC 项目贡献）；
- 不做渠道佣金/居间费自动化（单独政策）；
- 不做补贴/绿证/碳收益分配；
- 不做多法人/多区域/多币种复杂合并；
- 不做 AI 评分（只做证据摘要/缺口检测，评测门禁通过前不评分）；
- 不做全量 HRIS/ payroll。
