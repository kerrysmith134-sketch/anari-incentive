# 首个 wedge：充电桩设备销售

**日期**：2026-10-28  
**适用对象**：Anari Energy 及同类充电桩设备企业  
**状态**：P0 试点设计，待用 5–10 个真实设备销售订单验证  
**明确边界**：首期做**设备销售**，不做 EPC 工程、不做充电站运营、不做 O&M 收益分成。EPC 只保留为后续扩展示例。

> 一句话：充电桩设备销售是 N-Perform 的天然 wedge——订单金额高、参与角色多（销售/产品/供应链/质量/物流/财务/售后）、渠道与直销并存、回款与信用风险直接决定奖金、售后/质保/退货会追溯调整。用“订单归属人”或“销售额”分钱，既解释不了贡献，也管不住风险和现金。

---

## 1. 为什么设备销售适合做首个 wedge

| 特征 | 对贡献/激励系统的含义 |
|---|---|
| 标准产品 + 配置/定制 | 同一型号不同配置、不同价格、不同交期，贡献不能只看销售额 |
| 直销 + 渠道/经销商 | 渠道贡献与内部销售贡献要分开，不能重复计奖 |
| 订单金额高、批量大 | 单笔订单的毛利、折扣、账期差异大 |
| 信用/回款风险 | 签约不等于回款；坏账、逾期、质保扣款要能追溯 |
| 供应链/交期影响大 | 缺料、排产、物流会影响交付，不能全归销售 |
| 质量/售后/退货 | 质量问题、RMA、退货、保修会影响最终奖金 |
| 价格/折扣审批 | 低价拿单可能损害毛利，必须把“合同质量”纳入评价 |
| 渠道政策复杂 | 返点、价保、区域保护、项目报备，容易争议 |
| 证据分散 | CRM、ERP、生产/质检、物流、财务、售后系统各一段 |

这些特征让“按销售额提成”明显不够，也让通用绩效表单无法解释“这单为什么分给这些人”。N-Perform 的工作包+证据+贡献认定+确定性结算，正好对应设备销售的真实问题。

---

## 2. 买家与 champion

- **经济买家**：CFO/COO（关心毛利、回款、坏账、渠道成本、审计）。
- **champion**：销售运营/财务 BP/商务（关心对账、折扣审批、回款、争议）。
- **gatekeeper**：HR/法务/内控（关心程序、合规、员工关系）。
- **不是 CHRO 单人采购**：设备销售企业的痛点往往是“销售奖金怎么分、渠道和直销怎么算、坏账怎么扣”，而不是“绩效表单好不好填”。

---

## 3. 订单类型（首期只选一种销售模式）

| 类型 | 说明 | 首期建议 |
|---|---|---|
| **直销 DC 快充桩** | 直接卖给充电运营商/车队/能源企业，金额大、配置复杂 | **推荐作为首个 wedge** |
| 直销 AC 目的地桩 | 商场/园区/物业，标准化程度高、金额较小 | 第二期 |
| 经销商/渠道销售 | 区域经销商、系统集成商、EPC 伙伴采购设备 | 与直销并行，但政策要区分 |
| 框架/战略客户 | 年度框架、分批下单、价格协议 | 需要单独处理批次/价格保护 |
| 备件/售后销售 | 备件、维修、延保 | 单独政策，不与整机混算 |
| 出口/海外 | 认证、汇率、信用证、质保 | 后续，需多币种/贸易条款 |
| 项目型设备供货 | 只供设备，不承接施工/并网 | 可作为设备销售的一种，不按 EPC 算 |
| **EPC/充电站工程** | 设备+施工+并网+调试 | **首期不做**，后续扩展 |

首期建议：**一个法人、一个区域、DC 快充桩直销、5–10 个订单、20–50 人、一个季度**；渠道销售作为第二个配置模板，但不要和直销混在一个政策里。

## 4. 销售工作包模板（DC 快充桩直销）

| 工作包 | 主责角色 | 关键交付 | 验收/证据 |
|---|---|---|---|
| 商机与客户关系 | 销售负责人 | 商机、客户决策链、预算/招标 | CRM 商机阶段、客户会议、招标文件 |
| 技术选型/配置 | 产品/售前 | 功率、枪线、模块、协议、认证、站点适配 | 技术协议、配置单、客户确认 |
| 投标/报价/商务 | 销售/商务 | 报价、折扣、账期、交付条款 | 报价单、折扣审批、合同 |
| 信用/合同审批 | 财务/法务 | 客户信用、付款条件、违约责任 | 信用评估、合同审批 |
| 订单/排产/交期 | 订单管理/供应链 | 销售订单、排产、交期承诺 | ERP 订单、排产计划 |
| 采购/物料/成本 | 采购 | 关键物料、成本目标、替代料 | 采购订单、BOM 成本 |
| 生产/质检/出厂 | 制造/质量 | 生产、测试、出厂报告 | 生产记录、QC 报告、序列号 |
| 物流/发运/签收 | 物流 | 发运、报关/运输、客户签收 | 发货单、物流轨迹、POD |
| 回款/信用/坏账 | 财务/销售 | 首付、尾款、逾期、坏账 | 银行回款、账龄、信用记录 |
| 售后/质保/备件 | 售后 | 安装指导、RMA、质保、备件 | 工单、RMA、客户确认 |
| 客户成功/复购 | 销售/客户成功 | 复购、增购、推荐 | CRM 复购记录、客户反馈 |

**原则**：首期每个订单 8–12 个工作包即可；不要为每个动作建任务。C 级/胶水工作（协调、文档、客户关系维护）不逐项定价，但进入团队/岗位记分卡。

## 5. 证据地图

| 证据 | 来源系统 | 用途 | 风险 |
|---|---|---|---|
| 商机阶段/客户决策链 | CRM | 商机贡献 | 阶段可被人为推进 |
| 报价/折扣审批 | CRM/审批 | 合同质量、毛利 | 先低价后补审批 |
| 合同/技术协议 | 合同系统/CRM | 范围、价格、账期、质保 | 版本多，需版本化 |
| 销售订单/排产 | ERP | 订单交付 | 订单可拆/改 |
| BOM/采购价/成本 | ERP | 毛利、成本节约 | 成本分摊/关联交易 |
| 生产/QC/出厂报告 | MES/QMS | 质量、交付 | 事后补记录 |
| 发货/物流/POD | ERP/物流 | 交付、签收 | 签收人无权/代签 |
| 回款/账龄/坏账 | 财务 | 现金贡献 | 回款归属、坏账核销 |
| 售后/RMA/质保 | 售后系统 | 质量、客户成功 | 工单数量≠质量 |
| 渠道协议/返点/报备 | CRM/渠道系统 | 渠道贡献 | 渠道与直销重复计奖 |

**证据覆盖率**：销售/财务通常覆盖较好；产品/供应链/质量/物流/售后的“胶水工作”容易缺失。首期必须按角色测覆盖率，不要只看总体。

## 6. 贡献维度（建议）

| 维度 | 评估问题 | 证据 |
|---|---|---|
| 商机与客户关系 | 是否推动客户决策、拿到订单/框架？ | CRM 阶段、客户会议、合同 |
| 技术/配置 | 配置是否被客户接受、是否减少变更/返工？ | 技术协议、配置单、变更记录 |
| 商务/合同质量 | 价格、折扣、账期、违约条款是否合理？ | 报价、审批、合同、毛利 |
| 订单/交付 | 是否按期、按量、按质交付？ | ERP 订单、排产、POD |
| 成本/采购 | 是否守住目标成本、交期、供应安全？ | BOM、采购价、成本台账 |
| 质量/售后 | 是否有批次质量问题、RMA、退货？ | QC、RMA、工单 |
| 回款/信用 | 是否推动回款、控制逾期/坏账？ | 银行回款、账龄、信用记录 |
| 渠道/客户成功 | 渠道是否健康、客户是否复购？ | 渠道协议、复购记录、客户反馈 |
| 协作与风险 | 是否解除阻塞、跨团队协调、提前暴露风险？ | 依赖记录、会议结论、受益方确认 |

**不要**把“参与过”自动等于“贡献”；也不要把“销售额高”自动等于“每个人都贡献高”。低价拿单、坏账、退货都可能在后期反噬。

## 7. 参考政策：CHARGING_EQUIPMENT_SALES_V1

这是首个租户的可执行参考政策，不是 Anari 的最终制度；数值需财务回测、法务审查、员工程序后生效。

```
basePool = min(订单毛利 × 3.5%, 120,000)
cashFactor = min(1, 已回款 / 开票额)
cashAdjustedPool = basePool × (50% + 50% × cashFactor)
afterSalesReserve = cashAdjustedPool × 3%       # 售后/退货准备金，暂不分配
payablePool = cashAdjustedPool − afterSalesReserve
channelPool = payablePool × 渠道分成比例
internalPool = payablePool − channelPool
个人金额 = internalPool × 经确认的贡献权重
```

**质量/信用门禁**：

- 信用未批准 → 阻断；
- 质量冻结（批次问题/召回/RMA 异常）→ 阻断；
- 有渠道分成但没有渠道伙伴 → 阻断；
- 回款为 0 → 仍可影子计算，但池按 50% 计；建议试点期先不发放，只做影子；
- 退货/坏账/质保扣款 → 通过 adjustment/reversal 处理，不覆盖历史。

**为什么这样设计**：

- 把“开票”与“回款”分开，避免销售签单拿钱、公司承担坏账；
- 把“售后准备金”显式化，避免当期发完、后期退货/质保无钱可扣；
- 把“渠道分成”单独拆出，避免渠道和直销重复计奖；
- 把信用/质量作为硬门禁，避免“低价+高风险”订单也能拿奖金；
- 贡献权重来自工作包+证据+人工认定，不按岗位平均分。

**参考 fixture**：`fixtures/orders/equipment-001..005.json`，覆盖直销、渠道、封顶、备件、框架订单。

> EPC 项目政策 `CHARGING_PROJECT_CONTRIBUTION_V1` 仍保留在代码中作为后续扩展示例，但**不是首个 wedge**。EPC 涉及施工、并网、安全、质保金，工作包、证据和风险与设备销售不同，不能直接混用。

## 8. 行业特有的风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 价格/折扣失控 | 低价拿单、毛利被侵蚀 | 折扣审批、毛利底线、合同质量进入贡献维度 |
| 信用/坏账 | 客户逾期、坏账、账期拉长 | 信用门禁、现金因子、坏账 clawback |
| 渠道冲突 | 直销/渠道抢单、重复计奖 | 项目报备、渠道归属规则、互斥/叠加配置 |
| 渠道返点/价保 | 返点、价保、区域保护 | 渠道政策单独配置；渠道池与内部池分开 |
| 库存/交期 | 缺料、排产延误、超期库存 | 交付贡献区分可控/不可控；供应链指标 |
| 质量/召回 | 批次问题、RMA、退货 | 质量门禁、售后准备金、追溯扣款 |
| 定制/配置错误 | 配置不符、返工、客户拒收 | 技术协议、配置单、验收证据 |
| 客户集中度 | 大客户依赖、议价压力 | 客户组合/复购指标；不只看单一大单 |
| 关联交易 | 价格/成本可操纵 | 财务审计、独立复核、转移定价 |
| 出口/汇率 | 汇率、信用证、认证 | 后续多币种/贸易条款；首期不做 |
| 售后 SLA | 响应/维修不及时 | 售后工单质量；不与整机销售混算 |
| 备件/延保 | 单独收入、单独贡献 | 单独政策；不要混进整机订单 |

## 9. 试点范围与验收

**范围**：1 个法人、1 个区域、DC 快充桩直销、5–10 个订单、20–50 人、1 个季度；手工证据 + 1 个真实连接器（CRM 或 ERP）；影子结算，不产生付款效力。

**验收指标**：

- 证据覆盖率 ≥70%（按角色分层；销售/产品/供应链/质量/物流/财务/售后分别看）；
- 员工补充证据 ≤30 分钟/周期；销售运营/财务复核 ≤2 小时/周期；
- 贡献争议率 <10%；申诉处理时限可满足；
- 财务对账差异 0；独立 CSV/表格复算差异 0；
- 信用/质量/渠道门禁 100% 生效；
- 员工信任/程序公平不低于基线；
- 法律门禁（民主程序、告知/签收、最低工资/扣款、DPIA）完成。

**Kill criteria**：证据覆盖率 <50%；员工 >30 分钟；争议率 >10%；财务无法对账；信用/质量门禁被绕过；法律审查不通过；员工普遍认为这是监控系统。

## 10. 首期明确不做

- 不做 EPC 工程/施工/并网/质保金；
- 不做充电站运营收益分成；
- 不做 O&M 收益分成/可用率奖金；
- 不做渠道佣金/返点自动化（渠道分成只做“内部池拆分”，不自动结算给伙伴）；
- 不做补贴/绿证/碳收益分配；
- 不做出口/多币种/信用证；
- 不做多法人/多区域复杂合并；
- 不做 AI 评分（只做证据摘要/缺口检测，评测门禁通过前不评分）；
- 不做全量 HRIS/payroll。
