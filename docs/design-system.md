# Operations console design system

The console is a React 19 SPA in `apps/web`. It has no external UI or chart
library: semantic HTML, CSS custom properties and a small shared component
module are the design system. This document is the contract for adding a page
without making the console feel assembled from different products.

## Principles

1. **The API is the source of truth.** The console renders server state and
   sends explicit commands. It never computes a money movement, approval result
   or policy decision locally.
2. **Density with calm.** Operational tables are compact, but surfaces, type
   hierarchy and spacing keep the page scannable. Numbers align; prose wraps.
3. **Colour never carries meaning alone.** Status is a labelled badge with a
   marker, not a coloured dot by itself. Focus is always visible.
4. **One accent.** Deep evergreen is the product accent; categorical data hues
   are only introduced when a chart or meter genuinely needs identity. Status
   colours are reserved for status.
5. **Selected dark mode.** Dark palette values are chosen for the dark surface,
   not generated by inverting light tokens.

## Tokens

All tokens live in [`apps/web/src/styles/tokens.css`](../apps/web/src/styles/tokens.css).
Use roles, not raw hex values.

### Minimum type scale（NP-031，2026-11-21 审计）

界面文字一律 ≥12px，由 `tests/ui-type-scale.test.ts` 门禁强制：

| 层级 | 最小值 | 说明 |
|---|---|---|
| 元数据/徽标/脚注 | 12px | 原 9–11px 标签全部提升 |
| 表格正文 | 13px | 密表也不得低于此值 |
| 正文 | 14–16px | 页面主体阅读文字 |

第三方 provider logo 无官方资产，暂以文字徽标呈现（不虚构商标）；语义动作图标沿用既有 icon set。

| Group | Examples | Rule |
|---|---|---|
| Planes | `--bg`, `--surface`, `--surface-raised`, `--surface-sunken` | Page, panel and inset surfaces |
| Ink | `--ink`, `--ink-2`, `--ink-3`, `--ink-4` | Primary, secondary, muted and faint text |
| Lines | `--line`, `--line-strong`, `--line-soft` | Borders and separators |
| Accent | `--accent`, `--accent-hover`, `--accent-soft`, `--accent-ink` | Primary actions and selected state |
| Status | `--good`, `--warning`, `--critical`, `--info` (+ text/soft variants) | Only for state, with text |
| Sidebar | `--sidebar-bg`, `--sidebar-ink`, `--sidebar-muted`, `--sidebar-active` | Persistent navigation plane |
| Shape | `--radius-sm/md/lg/xl`, `--shadow-sm/md/lg` | Cards, controls and overlays |
| Space | 4px base rhythm, commonly 6/8/12/14/18/20/24px | Use CSS spacing, not arbitrary margins |

Typography is the system sans (`--font-sans`) across UI and figures; monospace
(`--font-mono`) is for ids, hashes, JSON and code only. Table numbers use
`font-variant-numeric: tabular-nums` via `.cell-num`/`.num`.

## Components

Shared components live in [`apps/web/src/components/ui.tsx`](../apps/web/src/components/ui.tsx).

- **AppShell** — fixed sidebar, sticky topbar, responsive drawer under 980px,
  skip link, breadcrumb and theme toggle.
- **PageHeader** — eyebrow, title, description and right-aligned actions.
- **StatTile** — KPI value, context line, optional meter. Use for single
  current values; do not build a one-bar chart.
- **Panel** — the standard content surface with optional title, subtitle and
  action; `flush` removes body padding for tables.
- **Badge** — status pill with a dot and text; tone comes from the status map.
- **Button / IconButton** — primary, secondary, ghost, quiet, danger; `sm` for
  table actions.
- **Modal** — portal dialog with labelled title, Escape close, focus entry,
  focus trap, body scroll lock and footer actions.
- **FormField / TextInput / Select / Textarea** — labelled controls with hints
  and inline errors.
- **Tabs** — underline tab row with optional counts; used for page-local views.
- **EmptyState / LoadingRows / ErrorNotice / InfoNotice** — first-class loading,
  empty and failure states; never leave a blank panel.
- **DefinitionList / CopyButton / Avatar** — detail metadata and identity.

## Page composition

- Every page starts with `PageHeader`; primary action on the right.
- Use a KPI row for headline numbers, then a split grid (main workflow + side
  context) on wide screens; stack under 1120px.
- Tables live in `Panel` with `flush` and a `.table-wrap` for horizontal scroll.
  Primary cell text uses `.cell-primary`; ids and secondary metadata use
  `.cell-sub` / `.mono`.
- Forms use `.form-grid` (two columns), `.field--full` for wide fields and a
  footer action in the modal. Every input has a visible label and `id`.
- Empty and error states explain the next action, not just the absence of data.

## Status language

`statusTone()` maps domain statuses to `success`, `warning`, `danger`, `info`,
`accent` or `neutral`. Approval, payment and lifecycle state always include the
word; separation-of-duties warnings use `InfoNotice` before the action. Never
style a status with an accent or categorical colour.

## Responsive and accessibility

- Sidebar becomes an off-canvas drawer at `max-width: 980px`; the scrim closes
  it and route changes close it automatically.
- KPI grids collapse 4 → 2 → 1; form grids collapse to one column.
- All controls are native buttons/inputs/selects with visible focus. Modal
  focus is trapped and restored; Escape closes.
- Tables stay in a scroll container rather than shrinking text below 12px.
- `prefers-reduced-motion` disables transitions and entry animations.
- Charts are intentionally absent from the dashboard. If one is added, follow
  the repository's data-visualisation guidance: pick the form before colour,
  validate the palette, keep one axis, provide a table view, and never use
  colour alone.
